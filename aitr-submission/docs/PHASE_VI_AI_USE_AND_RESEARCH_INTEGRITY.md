## Purpose
This document records the integrity requirements attached to the supplied Phase VI package. It is not a substitute for the student's authentic prompt history, tool logs, source checks, experiment logs, or institution-specific disclosure rules.

## Activity-log guidance
The source package contains a human–AI activity-log template with approximate entries for Phase IV and Phase V and explicit placeholders for missing evidence. It instructs the author not to invent dates, prompts, tool versions, errors, commits, or outcomes. Approximate dates must be checked against actual records, and placeholder entries must be completed or removed.

For each activity, record:
- actual date/time, tool/model, and prompt or action summary;
- AI suggestion/output and the human decision to accept, edit, or reject it;
- verification performed and evidence path;
- actual outcome and status.

## Evidence rules
- A generated notebook or script is not proof that it ran.
- A reported result needs its raw data, evaluator output, and provenance.
- A claimed fix should be supported by the actual diff or traceback.
- Commit information must be copied from the real repository history.
- Dates and model/tool names should be checked rather than guessed.
- Only include limitations, examples, and debugging history supported by project evidence.
- Check the institution's AI-use policy and disclosure requirements before submission.
